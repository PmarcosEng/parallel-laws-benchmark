1. Visão Geral

Este benchmark demonstra, de forma rigorosa e reproduzível, como as Leis de Amdahl e Gustafson se manifestam em cargas de trabalho reais. O projeto cobre dois domínios complementares:

  • Busca de eventos — quatro algoritmos (linear, binária, hash, reduce) em quatro modos de execução (serial, OpenMP, GPU sim, CUDA real).
  • Matemática densa — Monte Carlo Pi e Mandelbrot 2D, ambos com fração paralela fp≈100%, demonstrando o caso ideal para paralelismo.

Cada execução produz dois arquivos JSON em runs/: um para busca, um para matemática. O dashboard.html estático consome esses arquivos via drag-drop, sem servidor.

Objetivo didático: o aluno observa que algoritmos com fp alto (reduce, Monte Carlo) escalam bem, enquanto algoritmos com overhead de sincronização ou acesso serial (hash lookup pequeno, busca binária) podem ser mais lentos com mais threads — exatamente o que Amdahl previu.

Fluxo de medição (padrão)

/* Para cada algoritmo × volume: */
func_serial(dados, n, ...);          // warmup descartado
t0 = agora(); func_serial(...); t1 = agora();
func_serial(...);                    t2 = agora();
func_serial(...);                    t3 = agora();
t_serial = mediana3(t1-t0, t2-t1, t3-t2);

// Para cada contagem de threads:
func_openmp(dados, n, ..., th);     // warmup
ta = agora(); func_openmp(...); tb = agora();
func_openmp(...);                    tc = agora();
func_openmp(...);                    td = agora();
t_par    = mediana3(tb-ta, tc-tb, td-tc);
speedup  = t_serial / t_par;

5. Módulo generator.c

Gera arrays de eventos sintéticos com distribuições estatísticas reaisíticas. Semente fixa 42 garante reprodutibilidade entre máquinas.

Box-Muller — distribuição Normal

O campo valor segue N(μ=50, σ=15). A transformação Box-Muller converte dois uniformes U(0,1) em dois normais:

Z₀ = √(−2 ln U₁) × cos(2π U₂)   |   Z₁ = √(−2 ln U₁) × sin(2π U₂) valor = μ + Z₀ × σ = 50 + Z₀ × 15 
/* implementacao em generator.c */
static double box_muller(double u1, double u2) {
    return sqrt(-2.0 * log(u1)) * cos(2.0 * M_PI * u2);
}
ev.valor = (float)(50.0 + box_muller(u1, u2) * 15.0);

Processo de Poisson — timestamps

Os timestamps simulam chegadas de eventos com taxa λ = 100 eventos/segundo. O intervalo entre eventos segue a distribuição exponencial via inversa da CDF:

Δt = −ln(U) / λ U ~ Uniforme(0,1), λ = 100 ev/s → intervalo médio = 10 ms

6. Módulo search.c

Implementa 4 algoritmos × 4 modos = 16 funções de busca. Cada função retorna SearchResult contendo o array de resultados e o count. O caller deve chamar search_result_free() após usar.

1 thread, implementação direta sem pragma. Serve como baseline (T_serial).

Simula o algoritmo de dois passos CUDA na CPU: divide em blocos de 256, processa cada bloco sequencialmente. Não representa velocidade real de GPU — demonstra o algoritmo.

Exemplo: busca_linear_openmp

/* Varre o array em paralelo, cada thread guarda contagem local,
   depois barreira implícita reduz para o resultado final. */
SearchResult busca_linear_openmp(const Event *ev, int n,
                                    float min, float max, int threads) {
    int count = 0;
    #pragma omp parallel for num_threads(threads) reduction(+:count)
    for (int i = 0; i < n; i++)
        if (ev[i].valor >= min && ev[i].valor <= max) count++;
    /* coleta resultados numa segunda passagem serial */
    ...
}

False sharing no Hash Lookup: a tabela hash usa separate chaining. Se dois threads acessam buckets na mesma cache line (64 bytes), pode ocorrer invalidação desnecessária. O efeito é visível como speedup sublinear ou negativo com muitos threads.

7. Módulo sim_math.c

Implementa dois algoritmos matematicamente intensivos com fp≈100%: Monte Carlo Pi e Mandelbrot 2D. Ambos são compute-bound, sem acesso a arrays de dados, o que os torna benchmarks ideais para GPU.

LCG Thread-Safe

Para garantir reprodutibilidade e evitar contention em rand(), cada thread usa seu próprio gerador LCG com semente derivada do ID da thread:

static inline uint64_t lcg_next(uint64_t *s) {
    *s = *s * 6364136223846793005ULL + 1442695040888963407ULL;
    return *s;
}
static inline double lcg_double(uint64_t *s) {
    return (double)(lcg_next(s) >> 11) * (1.0 / (double)(1ULL << 53));
}
/* Semente por thread OpenMP: */
uint64_t state = 0xDEADBEEFCAFEBABEULL ^ ((uint64_t)tid * 6364136223846793005ULL);

Os multiplicador e incremento são os da Tabela 1 de Knuth (TAOCP vol 2), reconhecidos por boa equidistribuição em 64 bits. O shift >> 11 usa os 53 bits mais significativos para preencher a mantissa de um double IEEE 754.

Monte Carlo Pi

Gera N pontos (x, y) em [0,1)² e conta quantos caem dentro do quarto de círculo unitário:

π ≈ 4 × inside / N inside = #{(x,y) : x² + y² ≤ 1}, convergencia O(1/√N) 
double montecarlo_serial(long n) {
    uint64_t state = 0xDEADBEEFCAFEBABEULL;
    long inside = 0;
    for (long i = 0; i < n; i++) {
        double x = lcg_double(&state);
        double y = lcg_double(&state);
        if (x*x + y*y <= 1.0) inside++;
    }
    return 4.0 * (double)inside / (double)n;
}

Mandelbrot 2D

Calcula o número de iterações até divergência para cada pixel de uma grade side×side sobre [-2,1]×[-1.5,1.5], com max_iter=256. Retorna a soma total de iterações.

/* Para cada pixel (px, py): */
float c_re = -2.0f + (float)px * (3.0f / (float)side);
float c_im = -1.5f + (float)py * (3.0f / (float)side);
float z_re = 0.0f, z_im = 0.0f;
int iter = 0;
while (z_re*z_re + z_im*z_im <= 4.0f && iter < 256) {
    float tmp = z_re*z_re - z_im*z_im + c_re;
    z_im = 2.0f * z_re * z_im + c_im;
    z_re = tmp;
    iter++;
}
total += iter;

Balanceamento de carga: Mandelbrot é altamente não-uniforme — pixels dentro do conjunto (que atingem max_iter) são muito mais custosos que pixels que divergem rapidamente. Por isso a versão OpenMP usa schedule(dynamic,4) para distribuir linhas dinamicamente e evitar threads ociosas.

8. Kernels CUDA

Dois arquivos: search_cuda.cu (busca) e sim_math_cuda.cu (matemática). Todos os kernels targetam sm_75 (Turing, GTX 1650).

kernel_busca_linear (search_cuda.cu)

Grid-stride loop: cada thread varre múltiplos elementos com stride = gridDim.x × blockDim.x. Shared memory reduction → atomicAdd no resultado global.

__global__ void kernel_busca_linear(const Event *ev, int n,
                                      float min, float max, int *d_count) {
    extern __shared__ int sdata[];
    int gid = blockIdx.x * blockDim.x + threadIdx.x;
    int stride = gridDim.x * blockDim.x;
    int local = 0;
    for (int i = gid; i < n; i += stride)
        if (ev[i].valor >= min && ev[i].valor <= max) local++;
    sdata[threadIdx.x] = local;
    __syncthreads();
    /* reducao em arvore */
    for (int s = blockDim.x/2; s > 0; s >>= 1) {
        if (threadIdx.x < s) sdata[threadIdx.x] += sdata[threadIdx.x + s];
        __syncthreads();
    }
    if (threadIdx.x == 0) atomicAdd(d_count, sdata[0]);
}

kernel_montecarlo (sim_math_cuda.cu)

LCG 32-bit por thread (sem dependência entre threads). Grid-stride loop + shared memory reduction. Sem transferência H2D — tudo calculado na GPU.

/* semente por thread: */
unsigned int state = (unsigned int)(gid * 1664525u + 1013904223u) ^ 0xDEADBEEFu;
for (long i = (long)gid; i < n; i += stride) {
    float x = lcg32_float(&state);

    if (x*x + y*y <= 1.0f) local_inside++;
}

kernel_mandelbrot (sim_math_cuda.cu)

1 thread por pixel, float, max_iter=256. atomicAdd(d_total, (long long)iter) — suportado em CC ≥ 6.0 (GTX 1650 = CC 7.5).

__global__ void kernel_mandelbrot(int side, long long *d_total) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= side*side) return;
    int py = idx / side, px = idx % side;
    float c_re = -2.0f + (float)px * (3.0f / (float)side);
    float c_im = -1.5f + (float)py * (3.0f / (float)side);
    /* loop Mandelbrot ... */
    atomicAdd(d_total, (long long)iter);
}

Medição de tempo CUDA

cudaEvent_t t_start, t_stop;
cudaEventCreate(&t_start); cudaEventCreate(&t_stop);
cudaEventRecord(t_start);
kernel<<<grid, block, smem>>>(args);
cudaEventRecord(t_stop);
cudaEventSynchronize(t_stop);
float ms = 0.0f;
cudaEventElapsedTime(&ms, t_start, t_stop);
*t_kernel_s = (double)ms / 1000.0;

Notas de desempenho (GTX 1650 / sm_75): blockDim=256 é o padrão recomendado para Turing. O grid é limitado a 65535 blocos para evitar overhead de agendamento excessivo em n muito grande. Para busca linear, o gargalo é PCIe (H2D): copiar 960 MB leva ~120 ms, enquanto o kernel leva ~1 ms.

15. Medição de Tempo

A função agora() usa o método mais preciso disponível em cada plataforma:

#ifdef _MSC_VER
static double agora(void) {
    LARGE_INTEGER freq, cnt;
    QueryPerformanceFrequency(&freq);
    QueryPerformanceCounter(&cnt);
    return (double)cnt.QuadPart / (double)freq.QuadPart;
}
#else
static double agora(void) {
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return (double)t.tv_sec + (double)t.tv_nsec / 1e9;
}
#endif

Por que mediana de 3?

Cada medição é repetida 3 vezes (após 1 warmup descartado) e a mediana é usada. A mediana é robusta a outliers: um pico de latência do OS (interrupt, context switch, antivírus) que infle 1 das 3 medições não afeta a mediana, mas afetaria a média.

static double mediana3(double a, double b, double c) {
    if (a > b) { double t = a; a = b; b = t; }
    if (b > c) { double t = b; b = c; c = t; }
    if (a > b) { double t = a; a = b; b = t; }
    return b; /* elemento do meio após ordenação */
}

Precisão: QPC no Windows tem resolução de ~100 ns (freq ~10 MHz). clock_gettime no Linux tem resolução de ~1 ns. Para operações muito rápidas (< 1 µs), o overhead da medição pode ser significativo — aumentar o volume resolve.

Kernels CUDA: cudaEvent_t

Para operações assIncronos na GPU, QPC mediria o tempo de ida-e-volta incluindo sincronização da CPU. cudaEvent_t mede diretamente no hardware da GPU com resolução de ~0.5 µs.

16. Leis de Amdahl e Gustafson

Lei de Amdahl

Para um problema de tamanho fixo, seja fs a fração serial (não paralelizável). O speedup máximo com N workers é:

S(N) = 1 / (fs + (1 - fs) / N) Pessimista: para N → ∞, S → 1/fs. Se fs=0.1, max speedup = 10x independente de quantas GPUs.

Estimativa de fs a partir dos resultados

Invertendo a fórmula de Amdahl a partir do speedup observado com N threads:

fs = (N / S(N) - 1) / (N - 1) Usada no dashboard para calcular o "Teto Amdahl" (linha cinza pontilhada nos gráficos de speedup) 
function estimateFs(run, algo, vol) {
  const best = candidates.reduce((a,b) => b.speedup > a.speedup ? b : a);
  const v = (best.threads / best.speedup - 1) / (best.threads - 1);
  return Math.max(0.001, Math.min(0.999, v));
}

Lei de Gustafson

Para um problema que cresce com N (mantendo tempo constante), o speedup é:

S(N) = N - fs × (N - 1) Otimista: mais workers = mais trabalho no mesmo tempo. A curva "speedup com max threads × volume" demonstra isso.

Por que Busca Linear tem fs maior que o esperado? A parte serial é a fase de coleta de resultados (copiar ponteiros dos elementos encontrados para o array de saída) que não pode ser paralelizada trivialmente sem sincronização. Além disso, o workload é memory-bound — a banda de memória é compartilhada entre todos os cores, criando uma gargalo não capturado pelo modelo simples de Amdahl.
